## 1. 项目概述

### 1.1 项目背景

当前大学生（尤其是专科/本科生）在职业发展中面临三大痛点：

- **职业规划迷茫**：不知道"自己适合什么岗位""未来职业方向在哪"，缺乏科学评估工具；
- **技能与岗位脱节**：学习内容与目标岗位要求不匹配，导致"学了用不上"；
- **就业准备不足**：简历无法突出优势，难以通过企业筛选。

传统职业规划工具的局限：仅提供岗位列表未结合个人经历生成个性化路径；缺乏"学习-就业"的闭环；未利用 AI 识别"隐性差距"。

### 1.2 项目目标

构建一款 AI 驱动的全周期职业发展工具，围绕"**职业规划 → 技能学习 → 成果验证 → 成长可视化**"的闭环，解决"规划-学习-就业"断层问题。

### 1.3 核心价值

- **对用户**：解决职业规划迷茫、技能与岗位脱节问题，提升就业竞争力；
- **对比赛**：符合"聚焦真实场景、AI 智能体应用"定位，深度绑定 Trae 平台；
- **对社会**：帮助高校学生高效对接就业市场，缓解"就业难"。

## 2. 核心方法论：反向规划闭环

### 2.1 闭环流程

```
① 目标岗位锚定（分步输入 + AI 总结推荐）
        ↓
② AI 生成"理想简历"（该岗位优秀候选人的目标样板）
        ↓
③ 理想简历 vs 用户现状 → 语义级能力差距诊断
        ↓
④ AI 动态派发任务（完成一个解锁下一个）
        ↓
⑤ 成果物 AI 验证（A类硬技能 / B类软技能 分层）
        ↓
⑥ 验证通过 → 雷达图对应维度渐进抬升
        ↓
⑦ 达阈值 → 提示"建议重新诊断" → 更新差距清单与理想简历
        ↓ （回到③，形成动态迭代闭环）
```

**"反向"的含义**：先有终点（理想简历/目标岗位），再倒推路径（差距与任务），区别于传统"从现状推未来"的规划方式。

### 2.2 与传统方案的差异

| 维度 | 传统工具 | 职引未来 |
|------|---------|---------|
| 规划方向 | 从现状推未来 | 从目标倒推路径 |
| 差距识别 | 关键词匹配 | LLM 语义级识别隐性差距 |
| 学习闭环 | 点完成即结束 | 成果物 AI 验证"学即会" |
| 反馈机制 | 经验值/等级 | 雷达图渐进式生长（无游戏化数字） |
| 数据来源 | 人工编辑岗位 | 真实招聘数据（parquet） |

## 3. 技术选型

### 3.1 选型决策（含访谈修订）

| 层级 | 技术选型 | 说明 | 修订说明 |
|------|---------|------|---------|
| 前端框架 | **Vue 3**（Composition API） | 与开发者小程序技能栈一致 | 保持原方案 |
| UI 样式 | **TailwindCSS** | 替代 Element Plus，设计自由度高，适配深色科技风定制 | **修订**：原 Element Plus 模板感强 |
| 图表库 | **ECharts** | 雷达图渐进式生长动画、折线图、环形进度 | 保持原方案 |
| 构建工具 | **Vite** | 快速冷启动与 HMR | 保持原方案 |
| 后端 | **Trae 云函数**（逻辑编排器） | 所有 AI 调用、数据读写经云函数，离开 Trae 无法运行 | 保持原方案（比赛合规） |
| 数据库 | **腾讯云开发数据库**（NoSQL） | 存储用户、诊断、任务、成果物 | 保持原方案 |
| AI 对话 | **智谱 AI glm-4-flash / glm-4-plus** | 免费额度覆盖演示 | 保持原方案 |
| AI 向量 | **智谱 AI embedding-2**（768 维） | 岗位/经历向量化 | 保持原方案 |
| 认证 | **邮箱 + 密码** | 替代微信登录，Web 演示友好 | **修订**：原微信登录需企业主体 |
| 部署 | **云部署**（Vercel / Netlify） | 在线访问，评委可直接打开链接 | **修订**：原仅本地演示 |

### 3.2 为什么用 TailwindCSS 而非 Element Plus

- **设计自由度**：深色科技风需要大量自定义（霓虹紫高亮、渐变、毛玻璃卡片），Tailwind 原子类更灵活；
- **包体积**：按需生成 CSS，避免 Element Plus 全量引入的冗余；
- **AI 聊天/雷达图/任务卡片**等核心组件高度定制化，Element Plus 的模板反而成为束缚；
- **响应式**：Tailwind 的 `md:` `lg:` 前缀天然支持响应式断点。

### 3.4 智谱 AI 免费 API 方案

| 能力 | 模型 | 用途 | 说明 |
|------|------|------|------|

### 4.2 雷达图维度定义

雷达图固定 5 维（与岗位要求对比）：

| 维度 | 说明 | 数据来源 |
|------|------|---------|
| 技术能力 | 编程/工具掌握程度 | 任务验证通过率 |
| 项目经验 | 实战项目数量与质量 | 成果物累计 |
| 软技能 | 沟通/协作/表达 | B 类任务验证 |
| 行业知识 | 岗位相关领域认知 | B 类任务验证 |
| 工具熟练度 | 岗位工具掌握 | A 类任务验证 |

> **数据生成机制**：首次诊断由 AI 语义评估生成基准各维度得分（0-100），后续由任务验证通过驱动对应维度渐进抬升，而非仅靠任务完成数累加。即雷达图得分 = AI 基准评估 + 任务验证驱动的增量，避免"刷任务数"导致虚高。

## 5. 岗位数据：Parquet 整合方案

### 5.1 数据源

- **来源**：`https://download.jobscream.com/open-jobs.parquet`
- **处理策略**：按 6 大类别筛选，每类取 30-50 条高质量岗位，合计约 200-300 条，与文档规模一致

### 5.2 六大类别筛选

| 类别 | 关键词（标题/JD 包含） | 目标条数 |
|------|----------------------|---------|
| 产品 | 产品经理、产品助理、PM | 30-50 |
| 开发 | 前端、后端、Java、Python、全栈 | 30-50 |
| 设计 | UI、UX、视觉、交互、平面 | 30-50 |
| 数据 | 数据分析、数据挖掘、算法、BI | 30-50 |
| 运营 | 运营、用户运营、内容运营 | 30-50 |
| 市场 | 市场营销、品牌、新媒体、广告 | 30-50 |

### 5.3 数据处理流程

```
1. 下载 open-jobs.parquet
        ↓
2. Python 脚本解析（pandas + pyarrow）
        ↓
3. 按标题/JD 关键词分类到 6 大类
        ↓
4. 每类按规则排序（如：JD 完整度、去重），取前 N 条
        ↓
5. 数据清洗：去重、过滤空 JD、标准化字段映射
        ↓
6. 调用智谱 AI 提取结构化技能标签 + 生成岗位摘要
        ↓
7. 调用智谱 Embedding API 生成 768 维向量（批量预计算）
        ↓
8. 写入 jobs 表 + 向量缓存
```

### 5.4 字段映射（待实际 parquet schema 校验）

> ⚠️ 实际字段需在下载后用 `pyarrow` 读取 schema 确认，以下为通用映射预案：

| parquet 原始字段（预案） | 映射到 jobs 表 | 处理 |
|--------------------------|---------------|------|
| title | title | 直接映射 |
| description / jd | jd_text | 直接映射 |
| company / company_name | company | 直接映射 |
| location | location | 直接映射 |
| salary / salary_range | salary | 标准化格式 |
| category / tags | category | 映射到 6 大类 |
| - | requirements | AI 提取生成 |
| - | skills | AI 提取生成 |
| - | embedding | AI 预计算 |

### 5.5 数据初始化脚本

提供 `scripts/init-jobs.py`：
- 下载 parquet
- 分类筛选
- AI 增强提取技能标签
- 批量生成 Embedding
- 导出为 `jobs-seed.json` 供云函数初始化导入

### 5.6 岗位库更新机制

| 方式 | 频率 | 说明 |
|------|------|------|
| 重新跑初始化脚本 | 每季度 | 拉取最新 parquet，重新筛选入库 |
| AI 辅助扩增 | 按需 | 基于现有 JD 生成相似岗位变体 |

> **Parquet fallback 策略**：若 parquet 数据源不可用（如下载失败、服务中断）或格式变更（字段结构不兼容），系统自动 fallback 到本地缓存的岗位库（`jobs-seed.json`），并在管理后台提示「数据源异常，请管理员检查」。fallback 期间用户侧推荐流程不受影响，仅新岗位更新被阻塞。

## 6. 核心功能规范

### 6.1 模块一：职业规划与目标锚定

#### 6.1.1 功能描述

通过**分步输入 + AI 总结**的混合式引导，收集用户专业、兴趣、经历，AI 生成个性化职业方向推荐。

#### 6.1.2 引导流程（混合式，3-4 步）

> **修订说明**：原 v4.0 为纯 AI 多轮对话，访谈后改为分步输入 + AI 总结，兼顾体验速度与 AI 展示。

```
Step 1：基础信息
  - 选择专业（下拉，支持搜索，autocomplete）
  - 选择年级（大一-大四/应届）
  - 选择学校（可选）
        ↓ [下一步]
Step 2：兴趣方向
  - 多选兴趣标签（卡片式，如"技术研发/产品设计/数据分析/内容创作/商业运营/艺术设计"）
  - 偏好工作环境（多选：大厂/创业公司/外企/国企/远程）
        ↓ [下一步]
Step 3：经历描述
  - 文本框输入已有经历（≥50 字触发 AI 精准匹配，<50 字走规则兜底）
  - 可选上传简历片段
        ↓ [生成我的职业推荐]
Step 4：AI 生成推荐报告
  - 调用云函数：规则兜底 或 Embedding 精准匹配
  - 展示 TOP 5 岗位卡片 + AI 撰写的个性化推荐理由
```

#### 6.1.3 冷启动策略（两阶段）

| 阶段 | 触发条件 | 匹配方式 | 推荐结果 |
|------|---------|---------|---------|
| 规则兜底 | 经历描述 < 50 字 | 专业关键词 → 岗位映射表 | 3-5 个对口岗位 + "完善经历获更精准推荐"提示 |
| AI 精准匹配 | 经历描述 ≥ 50 字 | 智谱 Embedding + 余弦相似度 | TOP 5 匹配岗位 + 匹配理由 |

**专业-岗位映射规则示例**：

| 专业关键词 | 推荐岗位 |
|-----------|---------|
| 计算机/软件/信息 | 后端开发、前端开发、测试工程师 |
| 设计/视觉/数字媒体 | UI 设计、交互设计、视觉设计 |
| 金融/经济/会计 | 金融分析师、会计、风控 |
| 市场/营销/广告 | 市场营销、品牌策划、新媒体运营 |

#### 6.1.4 岗位向量预计算

200+ 岗位的 Embedding 在项目初始化时预生成并缓存到数据库。用户诊断时**不再调用 Embedding API**，仅调用一次 Chat API，大幅降低成本。

#### 6.1.5 输出展示

- 推荐报告区：卡片式 TOP 5 岗位
- 每个岗位卡片：匹配度进度条（紫青渐变）、匹配理由、技能要求摘要
- 卡片点击 → 岗位详情页
- 岗位详情页支持「设为目标岗位」操作

### 6.2 模块二：理想简历生成（核心卖点）

#### 6.2.1 功能描述

> **修订说明**：原 v4.0 该模块描述薄弱，本次细化落地。用户选定目标岗位后，AI 基于岗位 JD 生成一份"优秀候选人理想简历样板"，作为差距诊断的基准。

#### 6.2.2 生成逻辑

```
用户选定目标岗位
        ↓
云函数读取岗位 JD + 结构化要求
        ↓
调用智谱 glm-4-plus 生成理想简历（Prompt 见 10.2）
        ↓
输出结构化简历：教育背景 / 技能清单 / 项目经历 / 实习经历 / 证书
        ↓
存入 ideal_resumes 表 + 展示给用户
```

#### 6.2.3 展示形式

理想简历以**分段卡片**展示：

- **教育背景**：推荐学历、专业方向、相关课程
- **技能清单**：技术栈、工具、软技能
- **项目经历**：2-3 个典型项目描述（体现岗位核心能力）
- **实习经历**：相关实习方向建议
- **证书/成果**：加分项

**差距高亮**：用户当前未达成的项用 `#7B4FE0` 虚线下划线标出，点击可跳转到对应任务。页面顶部提供「差距高亮模式」开关。

### 6.3 模块三：技能差距诊断与学习路径

#### 6.3.1 功能描述

对比"理想简历/目标岗位要求"与"用户现状"，生成语义级技能差距清单，并结合在线课程资源生成可执行学习任务。

#### 6.3.2 三视图综合展示

**视图一：技能清单 + 状态标签**
- 清单列表展示目标岗位所有技能要求
- 每项标注状态：🟢 已掌握 / 🟠 待提升 / 🔴 未掌握
- 展开显示：详细说明、推荐课程、预计学习时长

**视图二：雷达图可视化对比**
- ECharts 双数据集（当前能力 vs 岗位要求）
- 5 维度：技术能力、项目经验、软技能、行业知识、工具熟练度
- 渐进式生长动画

**视图三：时间轴路径图**
- 横向时间轴展示学习路径
- 每个节点：任务名称、优先级、预计学习时长、推荐资源、任务状态

#### 6.3.3 实现逻辑

- **LLM 语义对比**：调用智谱 glm-4-plus，识别"隐性差距"（如同岗位要求"熟悉分布式系统"，用户简历写"了解微服务"，AI 识别为"待提升"而非"未掌握"）
- **课程资源整合**：结合 Coursera、edX、B 站等平台资源生成可执行任务
- **学习路径生成**：基于差距优先级和依赖关系生成时间轴

### 6.4 模块四：成果物验证（闭环核心）

#### 6.4.1 功能描述

⚠️ **v5.0 核心模块**，解决"学了 vs 学会了"的闭环真实性问题。用户完成任务需提交成果物，AI 自动验证通过后方可更新雷达图。

#### 6.4.2 任务分层（保留 A/B 分类）

| 任务类型 | 适用场景 | 成果物形式 | 验证方式 | 用户感知 |
|---------|---------|-----------|---------|---------|
| **A 类：硬技能** | 编程、数据分析、设计 | 代码片段、截图、文件上传 | AI 代码审查 + 结构化校验 | "交作业→AI 批改" |
| **B 类：软技能/认知** | 阅读、行业了解、方法论 | 30-100 字心得/收获 | AI 语义理解 + 关键词提取 | "分享→AI 拓展" |

> **文件上传范围限定**：首版 A 类任务的文件上传仅支持图片（png/jpg）和纯文本（txt）两种格式，暂不支持 Word/PDF 解析。代码类提交推荐直接粘贴到代码框，截图类提交走图片上传通道。

#### 6.4.3 验证流程

```
用户点击「完成任务」
        ↓
弹出成果物提交弹窗
        ├─ A 类任务 → 粘贴代码/上传文件 → AI 自动校验
        └─ B 类任务 → 输入 30 字以上心得 → AI 语义分析
        ↓
AI 返回验证结果（3-5 秒）
        ├─ ✅ 通过 → 雷达图对应维度抬升 + "技能解锁"特效
        └─ ❌ 不通过 → 返回具体修改建议 → 用户修改重新提交
```

#### 6.4.4 用户体验设计

- **心理暗示**：将"提交验证"重构为"获得 AI 导师反馈"，降低抵触感
- **即时反馈**：AI 验证 3-5 秒完成，通过后立即展示能力成长可视化
- **容错机制**：允许 3 次重新提交，不通过不扣分，只给修改建议
- **进度可视**：任务卡片显示"验证中 → 已通过/需修改"状态流转

#### 6.4.5 任务队列交互设计

任务列表**仅展示 3 个状态块**，避免长列表信息过载：

| 状态块 | 数量 | 展示规则 |
|--------|------|---------|
| 进行中 | 1 个 | 当前主推任务，高亮显示，直达成果物提交 |
| 待解锁 | 1-2 个 | 灰色半透明卡片，标注"完成上一任务后解锁"，不可点击 |
| 已完成 | 可折叠 | 默认折叠，点击「查看历史」展开，展示验证通过记录 |

**动态长出动画**：当前任务验证通过后，下一个待解锁任务**自动"长"出**——卡片从半透明渐变为高亮、伴随缩放+淡入入场动画（300ms），强化"解锁"成就感。已完成任务则自动归入折叠区。

### 6.5 模块五：个人成长数据看板

#### 6.5.1 功能描述

展示用户能力成长轨迹，以**雷达图渐进式变化**为核心反馈，**杜绝游戏化数值**。

#### 6.5.2 看板内容

| 区域 | 内容 |
|------|------|
| 顶部欢迎区 | 用户头像 + 姓名 + 个性化欢迎语 + 当前目标岗位 |
| 能力雷达图 | 当前能力 vs 目标岗位要求（ECharts，渐进式生长动画） |
| 能力匹配度趋势 | 折线图展示近 30 天匹配度变化 |
| 学习进度概览 | 环形进度图 + 完成任务数/总任务数 |
| 待办任务 | 今日推荐任务列表 + 成果物提交入口 |
| 岗位匹配 TOP 5 速览 | 卡片，点击进入诊断 |
| 快捷入口 | 4 个核心功能快捷入口卡片 |

#### 6.5.3 设计原则

> 彻底不要经验值。UI 上完全抹除"+30 分"、"Lv.1"这类数字。用户的核心驱动力是看到**雷达图线条在生长、匹配度百分比在提升、理想简历灰色项在变绿**。所有"经验值"相关 UI 替换为"技能维度可视化成长"。

#### 6.5.4 空状态设计

新用户无诊断数据时，看板**不展示空白图表**，而是展示引导态：

- **引导插画**：居中展示职业规划主题插画（如指南针+成长曲线）
- **主 CTA 按钮**：「开始职业规划」按钮，点击直接跳转 `/career-planning` 引导流程
- **辅助文案**："完成首次诊断后，这里将展示你的能力成长轨迹"
- **隐藏元素**：雷达图、折线图、进度环均不渲染，避免空数据误导

用户完成首次诊断后，引导态自动切换为完整看板。

## 12. 成本控制方案

### 12.1 核心策略

采用「**智谱 AI 免费 API 额度为主 + 国产开源模型备选**」双轨方案，实现项目运行期间零费用或极低费用。

### 12.2 成本优化技巧

| 技巧 | 说明 |
|------|------|
| 向量预计算 | 200+ 岗位 Embedding 在初始化时预生成缓存，用户诊断时不调 Embedding API |
| 结果缓存 | 相同画像输入复用诊断结果（7 天过期） |
| 限流保护 | 每用户每天 ≤ 10 次 AI 调用 |
| 模型分层 | 简单对话 → glm-4-flash；简历/诊断 → glm-4-plus（频次低） |

### 12.3 备选方案

| 模型 | 部署方式 | 硬件要求 |
|------|---------|---------|
| ChatGLM3-6B | Ollama | 16GB+ 内存 |
| nomic-embed | Ollama | 8GB+ 内存 |

切换成本：仅需修改云函数 AI 服务调用地址，业务代码零改动。

## 13. 非功能性需求

### 13.1 性能要求

| 指标 | 目标值 |
|------|--------|
| 首屏加载 | ≤ 2 秒 |
| AI 接口响应 | ≤ 5 秒 |
| 成果物验证 | ≤ 5 秒 |
| 页面切换 | ≤ 300ms |
| 岗位推荐（规则） | ≤ 500ms |

### 13.2 兼容性

| 平台 | 范围 |
|------|------|
| 桌面浏览器 | Chrome 90+, Firefox 88+, Edge 90+, Safari 14+ |
| 移动浏览器 | iOS Safari 14+, Chrome 90+, 微信内置浏览器 |
| 屏幕适配 | 320px - 1920px，响应式适配 |

### 13.3 安全要求

- 邮箱密码登录态校验（JWT）
- 密码 bcrypt 哈希存储
- API 限流：每用户每分钟 ≤ 20 次
- AI 接口限流：每用户每天 ≤ 10 次
- 输入校验：长度限制 + XSS 过滤
- 成果物验证服务端校验，前端不可绕过
- 密钥仅存 Trae 云函数环境变量

### 13.4 可用性要求

- 所有 AI 操作支持重试
- 表单数据自动暂存
- 加载状态有明确视觉反馈（骨架屏）
- 错误提示友好，附带操作建议
- **弱网处理**：AI 接口超时（>10 秒）自动重试最多 2 次；重试全部失败后展示友好提示引导用户检查网络，已输入的表单数据（成果物内容、心得文本等）自动暂存不丢失，用户恢复网络后可一键恢复继续提交
